# Статус реализации MVP

Проект: CRM Домашних групп (мультицерковная PWA).

## Что сделано

Проверено по коду и локальному запуску 15 июля 2026. После добавления логинов, соцвходов и бот-интеграций актуальная проверка: `make test` проходит, 42 теста и 216 assertions.

## Что нужно сделать дальше

Функциональный MVP из исходного большого плана закрыт внутри текущего PHP/MySQL/PWA-каркаса, включая новые запросы по профилю, пользователям, группам, восстановлению пароля и email-уведомлениям.

Остаются production-усиления и интеграции, которые требуют реальной инфраструктуры и регламентов:

- Настроить SMTP в `config/local.php` (`mail.driver=smtp`, хост Timeweb `smtp.timeweb.ru`) и cron для `bin/send-emails.php`.
- Проверить production-значение `url` в `config/local.php` и доставляемость ссылок из писем.
- Настроить настоящие VAPID-ключи WebPush (кнопка «Сгенерировать ключи» на `/security`) и проверить отправку в production-браузерах.
- Настроить внешний cron/supervisor для scheduler в production и мониторинг ошибок `email_notifications` / `notification_events`.
- Утвердить юридическую политику персональных данных и сроки хранения для реальной церкви. См. чеклист [docs/personal-data-rf.md](personal-data-rf.md); при подключении облачных ИИ к MCP отдельно оформить трансграничную передачу.
- Вынести ключ шифрования чувствительных заметок во внешнее хранилище секретов и добавить ротацию.
- Настроить регулярный off-site backup MySQL и периодическую проверку восстановления.
- Настроить реальные OAuth-приложения Яндекс/VK ID, redirect URI `/social/callback` и production-секреты в `config/local.php`.
- Настроить реальные webhook URL для Max/VK/Telegram и ключи `bots.max.*` / `bots.vk.*` / `bots.telegram.*` в `config/local.php` (включая `username` / `screen_name` для deep link).
- Получить и настроить `yandex.geocoder_key` в `config/local.php`, проверить лимиты и юридические условия геокодинга; при необходимости уточнить `yandex.geocoder_cache_ttl`, `yandex.geocoder_negative_cache_ttl` и `yandex.geocoder_timeout`.
- Провести end-to-end проверку привязки по deep link и отправки сообщений с реальными ботами.

## Статус интеграций с соцсетями и ботами

- Яндекс ID и VK ID реализованы как привязка внешнего профиля к существующему пользователю CRM и как публичное подтверждение профиля для заявки в домашнюю группу.
- Max / VK / Telegram реализованы как приватные каналы лидера и как входящий канал заявок новичков (канал показывается в профиле только если настроен токен; Telegram ещё и username).
- Deep link: Max `https://max.ru/<bot>?start=CODE`, Telegram `https://t.me/<bot>?start=CODE`, VK `https://vk.me/<group>?ref=CODE` (для VK нужно первое сообщение после перехода).
- Реальная отправка зависит от production-токенов, webhook-секретов, username/screen_name и настроенных callback URL.
